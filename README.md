# Nebula-Analyze
![Static Badge](https://img.shields.io/badge/image-analyze-orange)
![Static Badge](https://img.shields.io/badge/NASA-space_objects-blue)
![Static Badge](https://img.shields.io/badge/python-3.10+-green)

STEM-проєкт «Аналіз космічних об'єктів» — обробка та аналіз зображень NASA (JWST, Hubble, Chandra) класичними методами фільтрації, покращення контрасту, виділення контурів, сегментації та частотного аналізу.

Усі алгоритми реалізовані **вручну на `numpy`** (без OpenCV, scikit-image, PyWavelets, без ШІ/ML). `Pillow` використовується лише для читання/збереження файлів, `tkinter` — для інтерфейсу.

## Джерела зображень

Зображення завантажені з офіційного альбому NASA Webb: https://www.flickr.com/photos/nasawebbtelescope/albums/ (папка `images/`).

## Встановлення та запуск

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install numpy pillow
python main.py
```

Потрібно: Python 3.10+ та `tkinter` (входить до стандартної поставки Python для Windows).

## Інструкція користувача

1. Запустіть `python main.py`.
2. Натисніть **«Завантажити зображення»** (один файл) або **«Завантажити папку»** (пакетна обробка всіх `.jpg/.jpeg/.png/.bmp/.tif/.tiff/.webp`).
3. У лівій панелі **Algorithm** оберіть метод у списку **Choose Algorithm**.
4. Налаштуйте параметри методу повзунками та випадаючими списками (набір параметрів змінюється разом з методом).
5. Натисніть **Run Algorithm**. Для папки обробляються всі зображення; перемикатися між ними можна кнопками **◀ Попереднє / Наступне ▶** або списком **Файл**.
6. Результат:
   - зліва — оригінал, справа — оброблене зображення (області однакового розміру);
   - оброблене зображення автоматично зберігається в `output/` із суфіксом методу (напр. `name_clahe.jpg`);
   - нижня інфо-панель показує: `File`, `Native` (розмір у пікселях), `Size_orig`, `Size_proc`, `Time` (мс/с), `Saved` (відносний шлях); якщо даних немає — `-`;
   - метрики автоматично дописуються у `output/metrics/<назва_зображення>.json`.

## Реалізовані алгоритми

| Метод | Опис у проєкті | Параметри в GUI | Суфікс |
|---|---|---|---|
| **Медіанний фільтр (Хуанга)** | Ковзна гістограма по рядках, оновлення медіани за $O(r)$ на піксель; фільтрація каналів у просторі **Oklab** | `Kernel Size`, `Quantization Bins` | `_huang_median` |
| **Базовий медіанний фільтр** | Пряме сортування вікна (еталон для порівняння швидкості); працює у відтінках сірого | `Kernel Size` | `_basic_median` |
| **CLAHE** | Контрастне адаптивне вирівнювання гістограми по плитках із обрізанням піків та білінійною інтерполяцією; застосовується до каналу яскравості `L` в Oklab | `Clip Limit`, `Grid Size`, `Histogram Bins` | `_clahe` |
| **Метод Кенні** | Гаусове згладжування → оператор Собеля → придушення немаксимумів → подвійний поріг + гістерезис | `Gaussian Sigma`, `Gaussian Kernel Size`, `Low/High Threshold` | `_canny` |
| **Метод Оцу** | Глобальний поріг, що максимізує міжкласову дисперсію гістограми; результат — бінарна маска | `Histogram Bins` | `_otsu` |
| **Ерозія** | Мінімум у вікні структурного елемента (`rect`, `cross`, `disk`), кілька ітерацій | `Kernel Size`, `Structuring Element`, `Iterations` | `_erosion` |
| **Вейвлет-перетворення** | 2D DWT Хаара: режим `decompose` — мозаїка субсмуг LL/LH/HL/HH; режим `denoise` — м'яке порогування (VisuShrink) та зворотне перетворення | `Decomposition Levels`, `Mode`, `Threshold Scale` | `_wavelet` |

Допоміжно: власне перетворення **sRGB ↔ Oklab** ([src/color_spaces.py](src/color_spaces.py)) — перцептивно однорідний простір, у якому яскравість (`L`) відокремлена від кольору, тому CLAHE не спотворює кольори туманностей.

## Метрики

Після кожного запуску алгоритму метрики обчислюються автоматично ([src/metrics.py](src/metrics.py)) і зберігаються у файл `output/metrics/<назва_зображення>.json`. Якщо файл для цього зображення вже є — новий запис додається в масив `runs`, якщо ні — файл створюється.

| Ключ | Метрика | Формула | Що показує |
|---|---|---|---|
| `std` | Стандартне відхилення σ | $\sigma=\sqrt{\frac{1}{N}\sum(Y_i-\mu)^2}$ | Глобальний RMS-контраст обробленого зображення |
| `variance` | Дисперсія σ² | $\sigma^2$ | Розкид яскравості (σ у квадраті) |
| `mse` | Середньоквадратична похибка | $\mathrm{MSE}=\frac{1}{N}\sum(I_{orig}-I_{proc})^2$ | Відхилення результату від оригіналу (по каналах RGB) |
| `psnr_db` | Пікове відношення сигнал/шум, дБ | $\mathrm{PSNR}=10\log_{10}\frac{255^2}{\mathrm{MSE}}$ | Більше — результат ближчий до оригіналу; `null`, якщо MSE = 0 |
| `energy` | Нормалізована енергія гістограми | $E=\sum_{i=0}^{255}p_i^2$ | Однорідність розподілу яскравості (1 — один рівень, ~1/256 — рівномірний) |
| `entropy` | Ентропія Шеннона, біт | $H=-\sum p_i\log_2 p_i$ | Інформативність зображення (макс. 8 біт) |

Тут $Y$ — яскравість $0.299R+0.587G+0.114B$ обробленого зображення, $p_i$ — нормалізована гістограма яскравості (256 рівнів).

> **Примітка щодо інтерпретації.** `std`, `variance`, `energy`, `entropy` обчислюються для **обробленого** зображення; для порівняння з оригіналом запустіть метод і порівняйте з метриками «ідентичної» обробки або з самим оригіналом. `MSE` та `PSNR` змістовні для фільтрів та CLAHE; для Кенні, Оцу та Вейвлет-розкладу (результат — контури, маска, мозаїка субсмуг) вони лише показують міру відмінності від оригіналу, а не якість відновлення.

```json
{

  "runs": [

      "parameters": { "clip_limit": 2.5, "grid_size": "8x8", "n_bins": "1024" },
      "saved_path": "output\\cats-head-nebula_clahe.jpg",
      "processing_time_ms": 5.0,
      "metrics": {

```

## Структура проєкту

```
main.py             # точка входу (запуск GUI)
src/
  gui.py            # інтерфейс Tkinter
  run.py            # обгортки алгоритмів, таймер, словники ALGORITHMS / ALGORITHM_PARAMS
  methods.py        # реалізації алгоритмів на numpy
  color_spaces.py   # sRGB <-> Oklab
  proceed.py        # завантаження/збереження зображень
  metrics.py        # обчислення метрик та запис у JSON
images/             # вхідні зображення
output/             # результати обробки
output/metrics/     # JSON з метриками (по одному файлу на зображення)
```
